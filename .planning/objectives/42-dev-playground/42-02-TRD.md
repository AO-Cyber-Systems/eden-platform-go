<objective>
Hand the developer a working session with no interactive login — by minting a real token
for a real user, not by turning authorization off.
</objective>

<authenticate_do_not_exempt>
There are two ways to remove a login prompt. Only one is acceptable.

WRONG: make procedures public, or short-circuit the interceptors. This teaches a false
model — the developer builds against a system whose authorization does not behave like
production, and discovers the difference in staging.

RIGHT: seed a real user (TRD 01) and mint a real token for them through the production
JWTManager. Every interceptor stays on. Every RBAC decision is genuine. The ONLY thing
removed is the interactive step of typing credentials.
</authenticate_do_not_exempt>

</execution_context>

<constraints>

  database URL or binds beyond loopback, exit non-zero with a clear message.
- Preview/serving port 8091 if one is needed. NEVER 8080.
</constraints>
